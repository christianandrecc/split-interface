## Precision note for the future handoff

R1 line57 says the sentinel replacement should “preferably” preserve length/page count. Its mandatory approved-world digestMismatch outcome and line61's retained-length/real-parser fault require the selected derivative to have the approved length and actually parse as one page. Treat those required assertions as controlling: a different-length or unparseable candidate does not satisfy this calibration and must block acceptance, not be relabeled a digest-only success. This is not a remaining specification blocker; the strict outcome/fault rows already settle the behavior. The handoff can state the requirement directly.

For the ownership schedule, later evidence should also show that the chosen caller view actually aliases the changed backing bytes, while the private retained snapshot's digest/pages remain original. Otherwise a test could accidentally measure a Foundation wrapper's prior copy. This is implementation/QA calibration of R1's explicit mutable-span requirement, not a new API or production-policy decision.
