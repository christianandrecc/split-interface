# Web compatibility review: GM13G G1 / AF1
November 6, 2026. Static, docs-only review. Candidate `1d1c087a83ae47fcb7905c98bdfcb0ecff23e051`; Markdown SHA-256 `10df910307b828b95f10c76dba8cee9d12540e36ace37dd6a06186ee2fabc9c3`.

**Verdict: keep the separate AF1 fixture design; request clarifications before core implementation.** G1 correctly distinguishes an immutable byte read from a legacy generated export and keeps S1/S2 and native 4f unchanged. ## What web49 actually does

- **Source of a generated record.** W6:154-201 builds a normalized agreement display model, potentially synthesizing legacy signature *display* records, but retains the incoming document separately as `exportDocument`. W7:164,219 prefers that field and can otherwise use `agreement.document`. W8:26-53 guards duplicate clicks and suppresses a later component-state update after unmount. Its ready state acknowledges a requested browser handoff, not a saved file or current access; the mounted check happens **after** the downloader.
- **Cache and list are not authorization.** W2:11-13,42-154 stores legacy JSON, including owner-keyed data; it does not cache provider artifact bodies. Unconfigured mode reads local records. Configured collection loading verifies the current user, calls the participant RPC, verifies the account again, merges only eligible local drafts, and marks them unpersisted (431-472). A 42501 returns an empty list; other failures can return scoped or legacy drafts. Local visibility/identity matching, a cache key, a timestamp, and “persisted” are not AF1 grants.
- **Export has an important exception.** W2:147-149,475-485 returns the caller's snapshot immediately when unconfigured **or** when draft/unsent. For a configured, non-draft sent record, it checks an active user and reads the account-scoped list; a failed read or missing ID throws, not a cached signed export. Unlike the list loader, the export helper does not recheck an expected account after the RPC. WSQL:227-237 returns a privacy-projected legacy JSON row, not an AF1 readRef/manifest or raw bytes. This is static migration source, not an observed deployed grant.
- **Generated PDF is not retained evidence.** W1:15-42 reads viewer settings, builds a new Blob, creates an object URL, clicks an anchor and later revokes the URL. W4:10-24 caches a promise for **fonts and branding assets**, not signed originals. W9:28 uses export-time/viewer context; W3:365-398 creates, labels and serializes a new document with optional history. W5:29-61 checks legacy in-app acknowledgement evidence; neither a status, timestamp, signature count, nor the visual verified label proves provider execution. WT:35-45 is existing test *source* for failure/no-render behavior, not a test run in this review.
- **AF-11 noninterference.** Explicitly classified, authorized legacy L may continue down this path with its historical JSON, unknown sentinel and acknowledgement method intact. For AF1/provider/unknown/denied/unavailable, route selection must precede *all* legacy snapshot, list/cache and renderer fallbacks. No legacy button handoff, settings/asset render, new object URL, badge, local fake array, old certified copy or reconstructed certificate on denial. Test a denied P and an authorized L with similar title/identifiers in the same view. Keep UI selection and source bytes distinct. S1:137-151 proposes server-side exclusion before legacy projection/normalization; this is not implemented by a UI branch. Already delivered copies are not recalled.

**No compatible existing decoder.** N1:4-63 requires two ordered simulation entries, 1-4096 bytes encoded as base64, native tuple headers and fixture-specific digest inequalities. N2 contains text samples, not PDFs; NV:52-61 presents metadata. N3:69-94,255-273 stages both items with account/selection/denial checks; N4:67-77 has an optional exact-revision comparison, not AF1's mandatory current-view check. Preserve those accepted behaviors, not their wire meanings. G1 instead needs raw bodies, manifest revision, entry order, explicit per-entry grants, P2 cardinality and a different provenance. M1's prepared ASCII and absent evidence likewise cannot become an AF1 seed by changing a media label. N2's cited range in G1:16 runs past the file end; the relevant construction ends at line 60. This is a citation nit, not a protocol blocker.

## Minimum shared contract for the next review

**Namespace and envelopes (G1:48-62).** Exactly three root literals on each serialized response metadata root: `fixtureContractVersion=split.execution.artifact.fixture.proposal.v0.1`, `origin=syntheticFixture`, `fixtureSetId=af1-pdf-samples-v1`. No S1 `contractVersion`, native header or `providerOriginal`. Under those roots: projection success adds only `replyKind=sampleProjection, requestId, projection`; manifest success adds `replyKind=sampleManifest, requestId, readRef, manifest`; bytes metadata adds `replyKind=sampleBytes, requestId, readRef, manifestId, manifestRevision, entry, contentLength, contentType`; failure adds `replyKind=failure, requestId, code, recovery`. No body, tuple, hidden existence, operation/session receipt or stored provider error in a failure. No root literals implicitly copied into nested objects. Requests are currently logical call arguments, **not** an adopted S1 HTTP command envelope: specify any serialized request vector separately. Optional manifest lookup ID omitted, never null; when supplied compare exactly, and when omitted pin the selected current manifest/revision from the authorized reply, never a selector for arbitrary storage.

**Projection and readRef.** The projection has exactly G1:52's 14 names: `executionId,projectionRevision,observedAt,frozen,attempt,ownParty,accessRevision,viewTag,selection,completionState,packageState,requiredParties,unresolvedRecipientCount,permittedReads`. Selection `current|superseding|superseded`; completion `simulatedPending|simulatedComplete`; package `absent|assembling|ready|failed|quarantined`. Only unique `readSampleManifest|readSampleBytes` hints, never authorization. Freeze whether permit ordering matters. Required parties: `{partyId,participantId,state,ambiguous}`, state `pending|signed|declined|unknown`, genuine boolean ambiguity. Preserve individual facts separately from package readiness. `AF1ReadRef` contains only `executionId,expectedProjectionRevision,frozen,attempt,ownParty,accessRevision,viewTag,selection`. Clarify the exact copy/rename from `projectionRevision`, never default from the latest record or silently substitute `sourceSheetRevision`. `observedAt` is not an ordering key.

**Expand the nested values.** S1:45-57 provides the vocabulary: `OwnParty={accountId,partyId,participantId}`; `FrozenBinding={sheetId,proposalId,snapshotId,sourceSheetRevision,policyRevision,signerBindingRevision,termsEncodingVersion,termsVersion,templateVersion,rendererVersion,signedTermsDigest,requiredSignerSetDigest,documentSetDigest,documents}`; each prepared document is `{documentId,order,preparedDigest,byteLength,mediaType}`. Attempt is `{attemptId,attemptGeneration,requestIntentId,providerAccountConfigId,providerEnvironment,providerAccountId,envelopeId}`; **required known envelope** for AF1, unlike S1's unknown-create case. Accept the selected synthetic environment only; a recognized production string still cannot substitute for a demo-bound seed. Distinguish durable intent ID from diagnostic request ID. Expand each digest recursively and decide object versus scalar once; no dual acceptance. Specify exact synthetic terms/signer/document-set hash preimages or an immutable trusted mapping; do not inherit GM13E's ASCII recipe, legacy display normalization, or JSON object insertion order as a cryptographic encoding.

**Scalars and decoding.** Spell out UUID versus opaque-ID fields, canonical fixture spelling and equality (including no trimming, case folding or Unicode normalization), nonempty strings, actual booleans, and RFC3339 UTC fixture precision. Define all integer fields: positive revisions, nonnegative generation/count/orders, positive byte lengths. G1's per-artifact, package, UTF-8 metadata, revision and generation ranges are *fixture bounds only*. Include limits and one-over vectors; specify which fields each bound covers, whether metadata ceiling applies per root and whether prepared reference bytes count in the retrieved package budget. Reject unknown fields at every level, explicit null on omitted/required fields, strings-as-numbers, boolean-as-number, fractions/unsafe integers and duplicate IDs. Agree on handling duplicate JSON member names, exponent/integral-decimal spellings and negative zero at the raw decode boundary; ordinary JS parsing or a Swift keyed decoder may erase distinctions before a typed validator sees them. Define whether vectors are lexical or semantic rather than expecting a typed object to recover lost syntax. No production Int64/JSON policy chosen.

**Document and byte binding.** Manifest keys exactly `manifestId,manifestRevision,executionId,frozen,attempt,provenance,entries`; provenance only `syntheticFixture`. Entry keys exactly `artifactId,role,order,digest,byteLength,mediaType,retrievedAt,reconciliationId,documentId?`. Use the proposed consecutive artifact order from 0; spell out prepared order base/contiguity too. P1: one executed sample then one completion-evidence sample; P2: both executed samples in exact frozen document order then one completion-evidence sample. Each executed entry has the corresponding nonempty documentId; certificate omits it (null is not omission). No duplicate/missing/extra IDs or silent sort/truncate. Do **not** reject repeated executed roles in P2; uniqueness is artifact ID and document correspondence, not unique role names. Define reconciliation-ID scope from the trusted seed rather than assuming all IDs unique or all identical. Preserve prepared/executed/certificate digests independently; equality or inequality is not evidence of execution.

**Bytes and errors.** The injected pair is `{metadata,body:Data/Uint8Array}`; no JSON-base64 payload, path or URL. Compare metadata to the exact authorized request, pinned manifest ID/revision, *entire* frozen/attempt/ownParty tuple and selected entry. Compare length to both retained entry and bounded actual bytes, content type to the literal `application/pdf`, digest over the exact selected bytes to an independently retained digest. Take an owned immutable copy for validation/publication or prove exclusive ownership: hash only the Uint8Array view, not its whole backing buffer. Test prefix/suffix subviews, mutation after validation, dishonest length, same-length substitution and a body whose adjacent declared digest matches the attacker, not the manifest. No transcoding, concatenation, cover, resize or PDF reserialization. Check bounds during intake, not only after an unbounded buffer allocation; typed in-memory fakes can establish checks at their own boundary, not real transport allocation limits.

A later adapter must distinguish a complete 200 PDF from a 206 (even though both satisfy `response.ok`), redirect/followed redirect, empty/truncated or encoded response, a 200 error JSON, failure JSON carrying success headers, and thrown decode errors. Do not follow a redirect and then judge only final status; reject before handoff. Define metadata-to-body correlation and header normalization, absent/conflicting length/type, no-store and unsupported range semantics before claiming HTTP parity. G1's local pair alone does not define where HTTP metadata travels. No new production transport policy is selected. For `denied|staleRead|samplePending|integrity|unavailable|unsupportedFixture` and `none|readSampleProjection`, freeze allowed pairs, precedence and sanitized diagnostics; failure may trigger an explicit fresh projection read, never a signing/session/void operation. S2's standalone six-key 409 and its bearer-free receipt concern duplicate **session issuance only**: neither is an AF1 error, call credential, entitlement nor certificate.

## Publication, history and vector gates

1. **Principal/read authorization.** Inject the trusted principal and local account generation separately from serialized input. Check registry membership for the specific selected execution and explicit per-entry grants, including the certificate; compare body ownParty with the caller's canonical tuple. A/B seed positives do not confer universal certificate rights; C, D/revoked A/B, same-display-name/email, copied viewTag/ID or historical signer deny. For unauthorized callers, unknown/known-but-inaccessible resources must not differ in body/readiness. Use current authorization before disclosing stale-binding diagnostics. Do not confer identity from a digest or an RPC row.
2. **Whole-package publish.** Require independently known simulated completion; exact frozen required-party registry and signer correspondence; all uniquely signed, none ambiguous/missing/extra, zero unresolved; correct policy/selection, both read permits, exact manifest eligibility and all validated artifacts. Explicitly make non-ready states non-publishable. Stage each entry privately, and publish only the complete set. A certificate-only denial after positive document reads invalidates *all* package eligibility; it does not erase truthful individual signing facts. G1:90's “retain valid individual metadata” must not retain selected-entry bytes, titles, counts or readiness for a newly denied reader.
3. **Late successes and failures.** Capture principal/account generation, selected execution/selection epoch and mode, projection revision, frozen binding, full attempt, access revision, viewTag, local denial-observation revision, and manifest ID/revision once known. Recheck after every suspension, hashing/inspection, materialization and just before publishing. An old typed failure or thrown error has no trusted grant; use its local invocation stamp, not requestId as authority. A late stale error cannot clear a newer valid package, nor can stale success resurrect a newer denial. Specify equal-stamp concurrent operation ordering; deterministic holds must include denial after a previous member was staged, ABA switch away/back, unchanged execution ID with changed manifest, and fresh positive recovery. Clearing old eligibility applies only to the still-current attempt. No automatic replay.
4. **History versus current.** E1's immutable bytes may be read only after a fresh authorized explicit history selection. E1 completion during E2 viewing must never populate E2, mark E2 final, or become a fallback when E2 is pending/denied. Preserve both sources; tag historical display even when E1 is readable. Define the `superseding` case explicitly in fixture vectors without choosing real supersession/retention policy.
5. **Stage boundary.** First freeze small, clearly synthetic immutable assets and independently constructed expectations: raw prepared/executed/evidence bytes, roles, safe display labels, digest, length, page count, parser expectation, and sample environment/source bindings. Include valid-length/digest but unrenderable content; identify which layer detects it. No `%PDF` prefix, successful open, local sample, or hash proves signature/legal authenticity. Distinguish private `bytesValidated` from `displayEligible`; do not manufacture a successful parser result to approve the host. Materialization/viewer/share, cleanup failure and revocation after OS handoff remain separate native-host review. Do not infer recall of files already handed off.

**Decision requested from GM/shared + native owners:** publish a small AF1-only protocol/vector addendum covering W-AF1-1 through -5, with wire spelling, trusted seed oracle, byte custody, failure matrix, same-context race controls and core/host acceptance boundaries. Review those identical expectations in both languages before any separate code handoff. No production input limit, retention/access policy, SDK, storage, service or legal decision is needed to write this addendum. D01-D07 remain open. No claim of real per-read enforcement or actual provider-original validation.
