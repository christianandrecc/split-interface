No fixture/runtime code is authorized or written by this plan.** Inputs: exact [S1](beta-docusign-server-boundary-cutover-proposal-v0.1-2026-11-03.md) `536dfe65ad44a096c6939a2c5c150ab9ec21a508`, [S2](beta-docusign-server-boundary-s2-session-duplicate-2026-11-03.md) `0a5b9808667913033de8bc9efd77a7717dccbf50`, native S1 notes/S2 closure archived by GM, and [web review](https://github.com/christianandrecc/split-interface/blob/40b4a5fa4ace3b8bc69d62faa85c73e9fc70e17e/build-it-app-main/docs/beta-s1-s2-web-review-2026-11-03.md) (SHA256 `e05cc02de33c643a997d340a89af46f298a944a838f3b7b24e7f93edf7d86d2e`). Objective: implement, **only after a new bounded GM handoff**, a dependency-free in-memory semantic model that exposes unsafe policy, identity, idempotency, duplicate-session, event and stale-publication behavior through deterministic adversarial tests. No production enforcement, complete wire codec, real preparation/ceremony/PDF or hosted integration claim follows from passing it.

## Exact synthetic registry and assumptions

All identifiers/data below are public test values. They are neither real Supabase identities nor legal/person/recipient evidence. An injected trusted fixture principal models an already-authenticated caller; it does **not** verify JWTs, email ownership, authentication strength or DocuSign identity.

| Principal | Synthetic account UUID | Canonical binding and current grant |
| --- | --- | --- |
| A | `00000000-0000-4000-8000-0000000000a1` | Creator `party-a` / participant `creator`, activeAccepted in P, L and R. |
| B | `00000000-0000-4000-8000-0000000000b2` | Invitee `party-b` / participant `invite-b`, activeAccepted in P and L. |
| C | `00000000-0000-4000-8000-0000000000c3` | Outsider, no party/grant. Knowing any IDs does not add one. |
| D | `00000000-0000-4000-8000-0000000000d4` | Former accepted `party-b` / participant `invite-b` in R's immutable snapshot only; current grant revoked, accessRevision2. D is not B and is not silently reassigned into P. |

Sheet IDs are UUIDs `10000000-0000-4000-8000-000000000001` through `...000005`, respectively **P** providerRequired/policyRevision1, **L** legacyInApp/1, **U** missing policy, **X** unsupported/1 and **R** providerRequired/1. P freezes A/B; R freezes A/D, retaining its historical mapping after D revocation. L's draft/sent/final variants are separate fresh test instances, not concurrent contradictory states. Mixed-read fixture contains one genuine final L alongside P/U/X. L bytes include an unknown historical sentinel field and original acknowledgement-method provenance; tests compare exact bytes, never rewrite a live/historical record.

P's seeded values: proposal `proposal-p-1`, snapshot `snapshot-p-1`, execution `execution-p-1`, sourceSheetRevision4, policyRevision1, signerBindingRevision1, initial projectionRevision1/accessRevision1, ordered parties A/B, allocations7000/3000 units. Known attempt uses `attempt-p-1`, generation0, requestIntentId `request-p-1`, providerAccountConfigId `cfg-fixture-1`, providerEnvironment `demo`, providerAccountId `provider-account-fixture`, envelopeId `envelope-fixture-1`; these are literal fixture references with **zero demo-service calls**. Each test creates a fresh fixture world; unknown-create cases omit envelopeId. Per-account operation IDs remain separately scoped, with stable keys `request-A-1`/`request-B-1`; session O1/O2 use exact S2 rules.

**Fixture-only policy, not production defaults:** clock starts `2026-11-03T21:00:00Z`, advances manually without waiting; modeled session validity60 seconds and replacementAllowed is an explicit injected boolean. Lookup deadline is stored per fake dispatch; the seven-day boundary vector is `2026-11-10T21:00:00Z`, tested before/at/after. All operation/dedupe records survive the entire test world; there is no retention/deletion worker. One seeded prepared document is represented by deterministic ASCII bytes `FIXTURE PREPARED\n` and a SHA256; no PDF validity/rendering/signature placement is claimed even where a proposed media-type field says application/pdf. Synthetic terms/set digest input uses ordered, sorted-key, whitespace-free ASCII JSON with labels `fixtureEncoding-v1`/`fixtureRenderer-not-pdf-v1`. Do not equate that encoding, one-document seed or transient validity/retention with S1 D02–D05 decisions.

Public test HMAC keys are literal `split-fixture-hmac-v1-public` and `split-fixture-hmac-v2-public`; never obtain a secret. The fixture admission format is **not a real Connect schema**: raw UTF8 JSON fields are exactly `fixtureEventVersion:"gm13e.event.v1"`, configurationId, accountId, environment, envelopeId, eventId, eventType, sequence. Baseline values match the known attempt, eventId `event-1`, eventType `envelope.completed`, sequence1. Header fixture uses `X-Docusign-Signature-1` with standard base64 HMAC-SHA256 over exact raw bytes. Test body cap1024 bytes; at most two allowed key versions, no compression or arbitrary encodings. These synthetic shape/budget/key-overlap choices test the admission algorithm only and do not settle production Connect D07. eventId/sequence/arrival time never authorize completion or establish trusted ordering.

## Injected interfaces and observable state

Use explicit JS value records/validated discriminants only for the selected operations, not a new generated production client contract. Constructors accept the following required seams; missing dependencies fail construction, without a live fallback.

| Interface | Required operations/invariants |
| --- | --- |
| `IdentityRegistry`, `PolicyStore` | Authenticate fixture principal; resolve account→sheet canonical party/participant/current grant and accessRevision; load authoritative policy outside editable JSON; reject missing/unknown policy. Freeze private maps by fixture seed; a modeled contact/profile change cannot rewrite them. |
| `Clock`, `MutationScheduler` | now/advanceTo and a deterministic serialized critical section around policy/operation/attempt decisions. Concurrency assertions exercise this model scheduler, **not Postgres advisory locks/constraints**. |
| `Ledger` | Immutable exact input bytes/digest, initiating account+kind+operationId, monotonic outcomeRevision, typed pending/confirmed/denied/unresolved state, request/attempt/dispatch-owner/lookup correlation. Same key+changed bytes conflicts; A/B different keys still share one active-or-uncertain attempt slot. No stored delivery marker/URL. |
| `FakeProvider` | Explicit create, own-session issue, lookup and canonical-state reconciliation stubs with independently configured results and call counters. Event body is never echoed back as authoritative provider state. Unknown request/session response and zero/multiple/wrong-scope lookup matches are independently injectable. No provider SDK/HTTP implementation. |
| `AdmissionInbox` | Authenticate raw bytes before trusted admission; bounded parse, config/account/environment/known-attempt checks, raw dedupe plus semantic effective-transition key; durable-in-model accepted/rejected receipt before acknowledgement. Inject receipt-persistence failure. This is in-memory custody, not durable production storage. |
| `PublicationProbe` | Capture principal/workspaceGeneration/selected execution+frozen+attempt/accessRevision before await. Revalidate after authorization and immediately before publication; a local observationGeneration invalidates all older suspended operations after denial, including delayed success/error. It may suppress a late value but must not silently cancel the ledger's external uncertainty. |

Named barriers: `beforeIntentCommit`, `afterIntentCommitBeforeDispatch`, `afterDispatchBeforeReply`, `afterIssuanceConfirmedBeforeDirectReply`, `afterAuthorizationBeforePublication`, `beforeInboxReceipt`, `afterInboxReceiptBeforeReconcile`, `afterProviderReadBeforePublication`. The driver releases promises explicitly, with no sleeps. Process loss reconstructs **only** a copied ledger/inbox/policy snapshot; volatile delivery markers, dispatch continuations and client leases are cleared. A copied pending dispatch is uncertain, not an available new claim. This is a synthetic restart/replay control, not a real database/object backup restore drill.

Legacy model entry points distinguish public wrapper, direct private/helper and trusted internal delegation. A user directly naming private/helper gets denial for **every** policy, including L; a trusted modeled wrapper/delegation still checks policy before effect spies. This simulates intended reachability/guard ordering only, never actual SQL EXECUTE privilege. Public L positive controls cannot accidentally authorize a private user call.

Counters are all model/fake effects: legacy row/registration/status/revision/response/agreement-audit/sync/notification/invitation-queue writes; legacy/document/metadata projection calls; dispatch claims; fake provider create/session/lookup/reconcile calls; inbox receipts/rejections/duplicate dispositions; effective lifecycle transitions; direct delivery markers; outcome receipt reads. Also assert **real transport calls0, ceremony launches0, artifact fetches0, finalizations0** in this scope. A denied legacy action has zero agreement effects; sanitized model security observations are separate. Frozen/legacy/source/confirmed-input bytes are compared before/after. No mock counter is evidence that an actual RPC/trigger/email worker ran or was prevented.

S2 session model uses a non-launchable private **delivery marker**, not an HTTPS URL, browser token or full live SessionLease codec. Only the original dispatch-owner continuation can consume that marker once. Confirmed identical duplicate returns exactly the six nonnull-string standalone409 `sessionOutcomeAvailable` failure; it has no CommandOutcome/receipt/session/bearer keys. An authorized outcome read returns confirmed receipt with delivery `notIncluded`; O1/input/outcomeRevision do not change. Pending/unresolved duplicates stay bearer-free and never subscribe to later delivery. A receipt clears issuance uncertainty without creating sessionReady or a ceremony. O2 is a new explicit driver intent with fresh checks and injected replacementAllowed; no callback, foreground, duplicate, read or restart may create it. Full production direct-session URL serialization is expressly outside first scope.

| SRV-09 | Suspend own session, known-execution status and outcome success/error after authorization; revoke/accessRevision/account/workspace/selection change or publish newer denial, then release old work. | SRV-10 | Exact raw HMAC succeeds; changed byte/pretty-print/missing/malformed signature/wrong key/scope/oversize rejects. Allowed synthetic key overlap positive control. Receipt persistence failure gives nonacknowledgement; accepted/duplicate/rejected authenticated dispositions acknowledge only after in-model receipt; zero canonical update from admission alone. |
| SRV-11 | Duplicate raw or semantically equivalent reordered body, replay, sent-after-completed, partial/extra required-recipient evidence and conflicting terminal facts: no repeated effective transition/audit or regression. Separate fake canonical read/full binding is required before modeled completion; contradictions quarantine. Evidence remains absent/finality not established; no artifact fetch/finalization. |

The tests must fail when the model is deliberately switched to unsafe modes: policy from replacement JSON; projection before guard; side effect before denial; duplicate dispatch; confirmed direct receipt/URL fallback; retry on missing lookup/restart; trust event completed/sequence alone; publish pre-denial suspended success/error. Keep these as explicit injected unsafe controls or bounded reviewer mutations outside the accepted candidate, with expected failing observations, not silent permanent alternative behaviors. Passing tests that exercise only self-authored helper outputs are insufficient; independently construct wrong bindings/raw bodies/expected snapshots/counters.
