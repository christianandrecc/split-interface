## 4. Inspector boundary and meaningful later acceptance

`PDF1Inspector.inspect(copying: Data, asset: trusted PDF1AssetHandle)` is a proposed synchronous, main-actor-isolated **local value call**, not a network API. The handle is minted from an immutable dataset instance/catalog; caller-supplied metadata/body pairs cannot add records. Check supported boundary/dataset/provenance and exact retained identity first; bound and synchronously copy the input, then compare exact length/SHA256 with the independent catalog. For this tiny experiment only, cap each file at 1MiB, ordered set at 3 files/3MiB, and positive page expectation at 1 or 2. These are authoring/test budgets, not D04 production limits or a hostile-parser timeout guarantee.

On the owned exact bytes, actually call `PDFDocument(data:)`. Nil rejects as unparseable. A nonnil result rejects if **isEncrypted OR isLocked**, then requires a nonzero pageCount equal to the independently reviewed expectation. Return only typed inspection facts or a rejection: dataset/asset identity, original digest and observed page/encryption/lock facts; **no PDFDocument, Data, URL, displayEligible, shareEligible, signer, execution/finality or permission token** escapes. Do not return a mock success, `%PDF` header verdict, borrowed mutable data or PDFDocument.dataRepresentation(). Compare input/catalog bytes before and after inspection; no reserialization, concatenation, cover or replacement of retained originals.

## 5. Remaining combination and host gates

PDF1 must earn its own separate acceptance; only the named AF1 memory core is currently accepted. No cast/flag can make AF1's ASCII body a PDF, and parser facts cannot finalize a package. Before any future combined synthetic package, both platform owners must review a new explicit dataset/version/adapter and independently frozen document/party/execution/attempt/version correspondence. Current trusted registry permission (both permits and **every** document/evidence grant), private load/observer ownership, authorization-before-diagnostics and synchronous final whole-set publication must remain independent of replaceable replies **and parser results**, including thrown parser errors and permission changes during inspection. The internal 4e2 authority seam is not a production or exported new service contract. Do not widen that accepted package as a shortcut. No combined permission behavior, full AF-07 or same-sheet lifecycle is closed by this asset plan.

H1 is a **later reviewed host assignment**: private per-materialization/presentation ownership/consumer leases; exclusive safe no-follow atomic files with protection/backup attributes; failed cleanup/orphan recovery; observable dismissal; one handoff per explicit share intent; and the inability to recall OS/external copies. No filesystem materializer, viewer/share contract expansion or host implementation is proposed here.

Real GM06D additionally needs retained actual executed originals and certificate; a reviewed authenticated metadata/byte-delivery/storage and per-read access contract; preparation/recipient/attempt binding, independent provider reconciliation, old-client server guards, cross-platform fidelity and recovery; then separate native host/device/accessibility and integration/release approval. D01–D07 production identity, content/parser/security/size, custody/access/retention, commercial/legal and operational policies remain unresolved. Synthetic renderability is no provider-original, real signature, malware-safety or legal-enforceability proof.
