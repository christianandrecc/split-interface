# GM-13A/B local execution alignment v0.1

November 3, 2026. **Docs-only local contract candidate for independent web/GM review.** Inputs: backend proposal `a5a5c26fd83bf6c4b8a675401dbac9f6ed856a5f` and native readiness/matrix `1a7deec7e88eac5d0d9fb526a99ec1d4cf92de63` (`ios/docs/DOCUSIGN_NATIVE_READINESS_2026-11-03.md` and `DOCUSIGN_NATIVE_FIXTURE_MATRIX_2026-11-03.md`). This addendum supplies concrete local DTO/state/fixture names; it is not a production API, schema change, mutual platform approval or prototype authorization. The [backend proposal](beta-docusign-local-contract-2026-11-03.md) remains the broader design record.

## Versions and construction boundary

- `contractVersion = split.execution.local.v0.1` and `fixtureVersion = split.execution.fixtures.v0.1` are required literal strings. Unknown/missing versions fail closed; no coercion from an existing `StoredSplitSheetDocument` or `SplitRecord`.
- Every DTO requires `origin = simulation`, `provider = docusign`, and `providerEnvironment = localSimulation`. These describe a fake integration target, not a provider connection. Other origins/environments are rejected by this local implementation.
- `executionPolicy` is required and is one of `providerRequired`, `legacyInApp`, `unsupported`. The execution DTOs/commands below accept only `providerRequired`. Legacy positive controls remain in their existing legacy renderer/store; selecting legacy/unsupported/missing policy cannot enter the new execution flow or become permission to sign. Simulation is provenance, not a substitute execution policy.
- First implementation is a separate Debug-only domain/store, an in-memory repository and a native simulated surface. Construction cannot instantiate Supabase, a provider SDK, URLSession/shared transport, an external browser or an OAuth client. No live URL, bearer token, production route, callback entitlement, shared RPC, file viewer/share implementation or canonical app-store mutation is included.
- All states display and announce **Simulated — no documents sent**. No real execution/verification badge, DocuSign certificate, provider branding or signature row is produced. Release cannot enter the fixture route through launch arguments or downloaded configuration.
- Prototype start requires GM-recorded contract alignment and independently accepted native count correction. This packet alone satisfies neither gate.

## Exact local vocabulary

| Dimension | v0.1 values and authority |
| --- | --- |
| Review readiness | `negotiating`, `ready`; fake server review projection. `ready` means freeze preconditions hold, not that an envelope/session exists. |
| Frozen preparation | `frozen`; returned only after explicit preparation. There is no automatic freeze on entry, refresh, recomposition or foreground. |
| Execution state | `notRequested`, `createPending`, `signing`, `completed`, `declined`, `voided`, `expired`, `superseded`; fake canonical execution projection. `completed` concerns all required provider recipients, not artifact readiness. |
| Resolution state | `known`, `uncertainCreate`, `uncertainSession`, `uncertainStatus`, `uncertainVoid`, `quarantined`; independent of last confirmed execution state. Terminal contradictions preserve the last confirmed facts and set `quarantined`; arrival order does not select a winner. |
| Evidence state | `absent`, `assembling`, `ready`, `failed`, `quarantined`; only fake server projection. |
| Canonical finality | `notFinal`, `final`; separate from execution/evidence. In simulation it is only the fake execution projection's finality and never changes the app's real agreement status. |
| Native activity | `idle`, `preparing`, `requesting`, `sessionLoading`, `sessionReady`, `presenting`, `awaitingConfirmation`, `unavailable`; transient main-actor state, not provider DTO values. `awaitingConfirmation` includes a return/Close whose canonical outcome is not yet known. |
| Required-party state | `pending`, `signed`, `declined`, `unknown`, plus `ambiguous: Bool`; preserve valid individual facts even when aggregate completion is denied. |

`final` is admissible only when execution is `completed`, resolution is `known`, evidence is `ready`, the exact current frozen binding still matches, every required party is uniquely signed/unambiguous, unresolved-recipient count is zero, and the complete artifact manifest is retained by the fake repository. Otherwise finality is `notFinal`. A contradictory projection claiming finality is rejected/quarantined, not repaired by the client. A valid completed/files-assembling projection displays simulated completion with evidence pending; no package download/share eligibility.

## DTO boundaries and required fields

All IDs are nonempty opaque case-sensitive strings except synthetic account UUIDs, which are validated/normalized as UUIDs. Digests are `{ algorithm: sha256, hex: <64 lowercase hexadecimal characters> }` computed over exact supplied fixture bytes. Positive revisions are signed 64-bit integers; generation counters are nonnegative. No field is inferred from title, document number, displayed name, email, callback or clock time.

`observedAt` and `expiresAt` are Int64 Unix seconds supplied by the injected clock; timestamps do not order projections or establish identity. `permittedActions` contains only `requestExecution`, `issueOwnSession`, `readExecution`, `readOperationOutcome`, `readManifest`, `fetchArtifactBytes`; its values cannot bypass local binding checks. Readiness itself governs explicit `prepareExecution` before a frozen projection exists. Command idempotency keys are scoped to active account + command kind + reviewed proposal/frozen execution + operation ID; reusing one with different content fails integrity. The fake repository also enforces one active attempt per execution across A/B's distinct command keys. Outcome/lease reads remain scoped to the initiating account; global execution readability does not expose another party's session outcome.

| --- | --- |

Frozen/execution/session state is absent. Its data are supplied by the injected fake repository, never ad hoc device authority. |
| `OwnPartyV01` | `accountId`, `partyId`, `participantId`; exactly one required accepted party binds to the active account. Other parties' account/contact fields need not be exposed in this client DTO. |

| `ArtifactBytesV01` | Version/provenance literals; manifest/entry/execution binding and exact bytes; 1–4096 bytes per fixture artifact, matching declared digest/length/type. The test-only 4KiB limit is not a future PDF/provider limit. No file/storage URL or secret-bearing redirect is modeled. |

**Cardinality resolution:** backend a5 describes one signable PDF; native 1a7deec permits an ordered set. Local v0.1 intentionally supports exactly one prepared sample and one executed-sample counterpart, plus one separate completion-evidence sample. It does not merge, omit or truncate a multi-document package. More/fewer/duplicate/out-of-order required entries are rejected. A future real wire contract must separately settle ordered multiple documents/attachments/provider certificate cardinality; v0.1 is no production limitation or entitlement assertion. `preparedDocumentDigest` must equal the one document-set entry's prepared digest. Fixture-only set/terms digests are SHA-256 of predetermined UTF8 JSON bytes with sorted object keys, preserved array order and no insignificant whitespace, generated by the fake repository; production document canonicalization remains unapproved.

The simulation's prepared, executed-sample and completion-evidence byte sequences are intentionally different, with separately computed digests. A later real certificate corresponds conceptually to the completion-evidence role, but this prototype neither creates nor claims such a certificate. The fake repository reauthorizes both sample artifacts for each read, including the completion-evidence sample; possession of its ID/digest or earlier successful PDF read is insufficient. Both A and B receive identical permitted sample bytes/digests while access remains account scoped.

`sourceSheetRevision` records the frozen source. `projectionRevision` is monotonically increasing within `executionId`, including execution/evidence changes; it is not the sheet revision, proposal number, attempt generation or a timestamp. Ordinary chat/audit can advance current sheet revision while frozen terms remain identical. Same proposal ID with changed terms, parties or required-signer digest fails binding. An older projection is ignored; an equal revision with different content is quarantined. A newer projection for another/superseded execution is never adopted into the selected current execution without explicit review.

## Minimal repository/store protocol

| Logical operation | Local command/result rule |
| --- | --- |
| `readReview`, `readExecution`, `readOperationOutcome` | Authorized reads only; zero creation, session issuance or state-change side effects. A/B are required accepted parties; outsider C receives typed denied/unavailable without another account's payload. |
| `prepareExecution(review, operationId)` | Explicit A or B intent; compare current expected revision/terms/party set and readiness. Freeze once and return execution ID plus projection revision1, execution `notRequested`, evidence `absent`, finality `notFinal`. Concurrent callers reuse the same current snapshot or receive a stale conflict. |
| `requestExecution(execution, operationId, stableRequestKey)` | A distinct explicit action after freeze; persist fake intent before response. One active attempt per execution even if A/B use different keys. Lost response retains correlation and `uncertainCreate`; refresh/relaunch reads outcome, never requests again automatically. |
| `issueOwnSession(execution, operationId)` | A third explicit action, available only for the current account's unique recipient in a known signing attempt. Re-entrant calls coalesce; uncertainty blocks new issuance. Confirmed expired lease may be replaced only through fresh explicit intent/read authorization, without another envelope attempt. |
| `readManifest`, `fetchArtifactBytes` | Fresh account/execution/artifact authorization and ready package required. Denial, integrity failure or access change clears stale preview/share eligibility. There is no cached certified fallback. |
| `handleReturnHint`, `closePresentation` | Local navigation operations only. Valid correlation may trigger an execution read. They cannot set completed, decline, void, freeze, request or issue a session. Forged, wrong-account, stale and replayed correlations are rejected or resolve by allowed read only. |
| Test-driver state injection | A fake-server-only seam supplies deterministic canonical projections/outcomes. It is not exposed as a production repository command, raw webhook listener or user `markCompleted` action. |

Every await captures active account and workspace generation plus the selected frozen/execution/attempt tuple. Verify them before publication; dismiss/clear leases, sample bytes and eligibility on account switch/logout/access loss. An initiating A request cannot publish after B becomes active. Closing/backgrounding does not mutate provider state. No offline consent/write queue or automatic mutation replay exists. Prototype restoration tests reconstruct an in-memory fake repository and read a known execution; they do not add protected storage or persist bearer-like leases.

Responses are the exact expected DTO or `ExecutionFailureV01`: required version/provenance literals, `code`, `messageKey`, `recoveryAction`, and optional `operationId` (required for uncertain commands). Codes are `denied`, `staleBinding`, `busy`, `uncertainOutcome`, `unsupportedContract`, `unsupportedPolicy`, `unsupportedLegacyProjection`, `evidenceUnavailable`, `integrity`, `unavailable`. Recovery is one of `none`, `readExecution`, `readOperationOutcome`, `refreshReview`; no recovery value authorizes a replayed mutation. Unknown versions/policy/provenance and recognizable legacy input map to the explicit unsupported codes below; other malformed fields or unknown enum/error codes map to unavailable. All enter native activity unavailable and clear session/artifact eligibility. A denied response contains no another-account execution body. The command/outcome binding must match the caller even when its error text sounds successful.

| Versioned error example | Exact local result and required observation |
| --- | --- |
| Missing/unknown contract or origin; a legacy document supplied as execution | `unsupportedContract` or `unsupportedLegacyProjection`, `recoveryAction = none`; no legacy parser fallback/session/artifacts. |
| Policy `legacyInApp`, `unsupported`, unknown or missing on requested provider execution | `unsupportedPolicy`, recovery `none`; preserve legacy records separately; no default in-house sign. |
| C requests A/B execution/session/evidence or own account/party is ambiguous | `denied`, recovery `none`; no other-account projection/session/bytes in the failure. |
| Same proposal ID with changed frozen terms/set/document digest | `staleBinding`, recovery `refreshReview`; preserve selected originals and block new actions until explicit review. |
| Create/session command reply lost for operation O1 | `uncertainOutcome`, `operationId = O1`, recovery `readOperationOutcome`; second create/issue remains blocked. |
| Confirmed completion with artifacts still assembling or freshly denied | `evidenceUnavailable`, recovery `readExecution` (or `denied`/none for revoked access); no prior sample-byte eligibility/fallback. |
| Wrong digest/length/type/cardinality or contradictory equal-revision content | `integrity`, recovery `none`; quarantine/clear stale eligibility, never normalize to a successful packet. |

## First implementation deliverable and approval boundary

After GM-recorded independent cross-review plus native count-correction acceptance: one separate Debug-only candidate containing the strict v0.1 models/decoder, `FakeExecutionRepositoryV01`, deterministic clock/account/suspended-result seams, isolated main-actor store and one simulated review/status surface. No production navigation/store mutation, real callback parser/registration, PDF/share feature, SQL, migration, provider dependency or real transport. Pure model/store tests cover required group cases; owner-run fixture UI covers distinct actions, Close, unavailable and completed/files-pending/ready simulation at ordinary/maximum text. Independently review exact SHA, source exclusions and side-effect counters; developer UI artifacts are a separate evidence layer.

Open beyond local v0.1: real endpoint/storage/byte-size/auth/identity/origin/callback/retention design, server pre-projection/read/write cutover, recipient/document correction policy, provider commercial entitlement and legal agreement review. These do not require invented production defaults to build the isolated simulation. This addendum is ready for web/GM acceptance or concrete correction; it does not authorize native code by itself.

Validation of this change is source/native-packet comparison, source-reference review and staged Markdown whitespace/link checks only. No runtime tests or provider calls are run for this docs-only milestone.
